# 執行時真正需要的套件。app/ 底下除了標準函式庫，直接 import 的只有 fastapi、
# uvicorn、openpyxl 三個；另外兩行（starlette／pydantic）是為了鎖住 FastAPI 行為
# 才一起釘死的間接依賴，理由見下方。
#
# 為什麼要單獨一份：部署端（助理的筆電）只需要「把系統跑起來」，不需要測試工具。
# 測試那組裡 playwright 最肥，而且裝完還會再去抓瀏覽器二進位檔，在連不到外網的
# 公司網路幾乎注定失敗——為了跑一個 Web 服務去裝它，等於平白多一個失敗點。
# notebook-package/service.ps1 只裝這一份。
#
# 完整清單（含測試工具）在 requirements.txt，它用 -r 引入本檔，所以這三個套件
# 只有這裡一個真實來源，不會兩邊漂移。
#
# ── 版本一律用 == 鎖死（2026-07-30 使用者指示）───────────────────────────
# 原本寫 >=，等於每台機器裝到的版本都不一樣，而且每次跑 update 都可能被上游
# 悄悄升級。工具撒到十幾台之後，這會變成「同一份程式碼在不同機器上行為不同」，
# 出事時無法重現，而且要一台一台去救。
#
# 這裡的版本＝開發機上跑完整測試（358 綠）驗證過的那一組。要升版是一個「決定」：
# 改這個檔 → 跑完整測試 → 進 patch，讓所有機器跟著 update 一起對齊，
# 不是讓使用者的機器各自漂到不同版本。
fastapi==0.136.1
uvicorn[standard]==0.46.0
# starlette 與 pydantic 是間接依賴，但它們直接決定 FastAPI 的行為，所以一起鎖：
# fastapi 0.136.1 對它們的要求只是 starlette>=0.46.0、pydantic>=2.9.0，範圍寬到
# 可以裝進不同大版本（我這台是 starlette 1.0.0——0.x 跳到 1.0 這種就是會出事的地方）。
# 不鎖的話，同一份 fastapi 在不同時間裝出來的機器行為會不一樣。
# 更底層的（anyio/h11/click…）交給 pip 解，它們的相容範圍穩定得多。
starlette==1.0.0
pydantic==2.13.4
# Excel 匯入/匯出。app/store.py 與 app/main.py 都用它，是執行時相依，不是只有測試要。
# 因為寫成函式內 import（延後載入），少了它系統照樣啟動，只有真的去匯入/匯出 Excel
# 才會炸——所以在早就裝過它的開發機上永遠看不出來，只有乾淨環境（CI、新部署的機器）
# 才會現形。local-ci 長期紅燈的真正原因之一，2026-07-21 補上。
openpyxl==3.1.5
