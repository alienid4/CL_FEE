## 跨系統整合：CL_WBS（2026-09-01 由 CL_WBS 端討論後登記）
CL_WBS 是另一套獨立的「專案進度追蹤」系統（Python stdlib、CPM 排程、階段關卡、
甘特圖），使用者拍板兩套系統走「模組化」——CL_FEE 管錢/合約、CL_WBS 管進度，
各自獨立開發不合併，之後用「關聯碼」串接（WBS 存一個欄位記住 CL_FEE 這邊的
案號，要看詳細金額/合約再連過去查）。串接時間點尚未定，但需要 CL_FEE 這邊
配合開放以下兩件事，接手時可以先規劃/預留設計，不用等真的排進時程才想：

1. **專案／案子的名稱搜尋 API**：現有 `GET /api/projects`、`GET /api/cases`
   只能整批撈（靠 `limit`），沒有名稱模糊搜尋。需要加一個查詢參數（例如
   `?q=關鍵字`），回傳 id、code、name 這幾筆符合的候選，讓 WBS 那邊做一個
   「搜尋關聯案號」的輸入框，使用者打關鍵字選一筆，不用手動複製代碼貼過去。
2. **機器對機器的驗證方式**：現有 `/api/auth/login` 是給真人登入用的帳密機制。
   WBS 是背景系統對系統呼叫，不會有真人在場輸入帳密，需要一個獨立的「服務對
   服務」驗證方式——例如發一組固定 API token（`X-Service-Token` header），
   範圍限縮在「查詢名稱、拿 code」的唯讀端點，不能用來改資料，避免 token
   萬一外洩還能拿去動 CL_FEE 的正式資料。

這屬於跨專案協調事項，實際排入時程前建議先跟使用者確認 CL_WBS 那邊的最新
狀態（存在 CL_WBS 的 memory `project_module_architecture.md`）。
