案例流程圖：中華電信板橋機櫃電力費調整

紅線代表此案例實際走過的流程：合約相關、非正式專案、產生付款、預算外、需處長 Release_Gate，後續收到帳單後才進核銷與發票。

案例摘要

這個案例可作為後續案例 HTML 的版型。

CASE-20260612-003 合約候選 預算外 待放行
Case 中華電信電力費調整 Email 來函，板橋機櫃電力費追加。
Contract 候選關聯 外部合約系統編號待勾稽。
Project 不建立 非正式專案，Project_ID 可空白。
Payment 3,000 / 月 定期付款 12 期，收到帳單後核銷。
Budget 36,000 / 年 預算外，需主管與處長確認。

紅線流程圖

灰黑線是系統完整流程，紅線是此案例的實際路徑。

紅線：本案路徑 虛線：未走或條件分支

本案判斷結果

判斷點 本案結果 建立資料
是否合約相關 是 建立候選 Contract_ID，待人工勾稽。
是否特殊關聯 是，費用調整 建立 Contract_Relation，型態為費用調整。
是否正式專案 否 Project_ID 空白，保留組別與標籤。
是否產生付款 是 Payment_Schedule：每月 3,000，12 期。
是否預算內 否 Budget_Check：預算外原因與年度影響。
是否需處長放行 是 Release_Gate：送主管與處長確認。

後續節點

Expense_Claim

收到中華電信帳單後建立核銷資料，需關聯 Payment_ID 與來源附件。

Invoice

發票由核銷資料建立，不直接掛在 Contract_ID 上。

Invoice_Allocation

本案預設單一費用單一發票，不需分攤；若一張發票含多筆費用才建立分攤。

audit_logs

新增 Case、候選合約、預算外原因、主管確認、處長放行與核銷更新都需留紀錄。
