欄位確認問題與系統建議

這頁用來跟業主確認欄位規則。系統設計問題由我方先給建議，只有來源、業務意義、責任人與例外規則才交給業主判斷。

回會議導覽

討論原則

不要請業主設計資料庫；請業主確認業務事實。

不要問 DB 拆表 要問來源與意義
我方直接建議：
Excel 全欄位先接住，原始資料進匯入暫存區。每個欄位都要有去處，正式資料再拆成 Case、Contract、Budget、Payment、Document、Audit 等資料表。
不要做歪：
不建議把 150 個 Excel 欄位做成一張 150 欄大表。那會變成網頁版 Excel，後續流程、權限、報表、稽核都會卡住。

欄位去處的我方建議

欄位類型 我方建議 業主要確認什麼
穩定主檔欄位 進正式主檔，例如費用項目、廠商、統編、合約期間、負責人。 欄位定義與哪一份 Excel 是主來源。
交易 / 明細欄位 拆成明細表，例如付款年度、月份、金額、期別、計費期間。 付款與核銷的業務規則。
1 月到 12 月欄位 正式資料轉成 year + month + amount；報表輸出時再轉回 12 欄格式。 報表是否仍要維持舊 Excel 樣式。
文件 checklist 欄位 轉成文件需求與文件狀態，不當一般文字欄位。 哪些文件必備、哪些可選、缺件時誰處理。
PDF 簽呈欄位 轉成簽呈文件、文字摘錄、頁碼與來源追溯。 PDF 內哪些內容必須抓出來給主管或處長看。
備註 / 差異說明 保留原文；若備註其實代表固定狀態，應拉成正式欄位。 哪些備註文字有固定流程意義。
計算欄位 由系統計算，例如未付款金額、完成度、合約天數、逾期與否。 計算公式與例外條件。
舊欄位 / 不再使用欄位 原始匯入保留，正式資料可標記不使用。 是否仍有人使用、是否要出現在報表。

各 Excel 來源的我方定位

來源檔 我方建議定位 請業主確認
費用項目整合23.xlsx 第一候選主來源，作為費用項目、廠商、付款、文件檢核、核銷工作清單的主要依據。 是否為目前最新、最可信的主檔。
費用合約整合(舊).xlsx 歷史資料與欄位對照，不建議覆蓋新版主檔。 哪些 Sheet 還在用，哪些只留歷史。
2026次月預計上簽項目.xlsx 上簽計畫來源，匯入成 Case / Signing Plan。 每月 Sheet 是否就是當月正式上簽計畫。
架構部續約合約進度.xlsx 續約任務看板來源，關聯合約到期與續約狀態。 續約狀態文字是否有固定定義。
資訊架構部處級專案進度追蹤總表 專案進度來源，只在正式 Project_ID 成立時關聯，不當費用主檔。 哪些費用案件需要連到專案。
PDF 簽呈檔 簽呈內容與決策依據，不是一般附件。 要抓哪些欄位、是否需頁碼追溯。

欄位問題的建議答案

問題 我方建議 只需要業主決定的部分
Excel 欄位是否全部進 DB？ 全部先進匯入暫存與來源紀錄；正式 DB 只存有業務意義的欄位。 哪些欄位仍有業務用途。
是否做一張 150 欄大表？ 不建議。會變成網頁版 Excel。 不需要問業主。
欄位同名但來源不同怎麼辦？ 建立來源優先順序與欄位對照表，不自動覆蓋。 哪一份檔案是主來源。
金額欄位很多怎麼辦？ 拆成預算金額、合約總金額、付款金額、核銷金額、發票金額、議價費用。 每個金額是否含稅、幣別、取數來源。
日期欄位很多怎麼辦？ 拆成合約期間、計費期間、申請日、付款月份、簽呈月份、專案起迄。 日期的業務定義。
狀態欄怎麼處理？ 統一狀態字典；原 Excel 狀態文字保留在來源欄位。 現有狀態文字如何對應。
PDF 怎麼處理？ 作為簽呈內容，需存頁碼、文字摘錄、關聯案件與人工確認。 PDF 內必抓欄位。
全文檢索怎麼處理？ 建議納入第一版核心能力，搜尋 Excel 原列、正式資料、PDF 簽呈內容與稽核紀錄。 哪些角色能搜到哪些資料，金額與簽呈是否要遮蔽。
AI 解析欄位可否自動寫入？ 不可。AI / PDF 解析只進建議區，人工確認後才寫正式資料。 誰有權確認。
Excel 回匯要不要保留？ 第一版建議保留，但回匯也要先進暫存與差異比對。 哪些報表或清單要回匯。

會議說法

可直接照念
我們不是要請您設計資料庫。資料庫怎麼拆表、欄位怎麼正規化，這部分我們會負責。
今天要請您確認的是三件事：第一，哪份 Excel 是正式來源；第二，這些欄位的業務意義與責任人是什麼；第三，PDF 簽呈裡哪些內容必須成為決策依據。
我們的建議是 Excel 全欄位先保留，正式資料再拆成案件、合約、預算、付款、核銷、文件與稽核，所以不會漏欄位，也不會把系統做成一張難維護的大 Excel。
