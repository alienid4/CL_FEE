FeeContractControl / FCCS

把「案件、合約、專案、付款、預算、核銷、發票」整理成可開發、可稽核、可驗收的流程藍圖

這份 HTML 不是把既有流程圖重新美化而已，而是把助理畫圖的目的落到工程語言：Case_ID 是事件主軸，Contract / Project / Payment / Budget / Expense / Invoice 是被條件建立的資料節點，每一次人工確認、匯入、回匯、核銷與發票分攤都要留下來源與 audit_logs。

Case_ID 主軸 Python FastAPI Microsoft SQL Server 人工確認優先 AI 不直接寫正式金額

為什麼助理要畫這張圖

因為這個系統真正難的不是畫面，而是「一筆請款或簽呈到底要不要建立合約、專案、付款、預算、核銷與發票資料」。圖的價值是把隱性判斷規則變成工程可以實作的分流器。

目的 1

建立共同語言

業務用「案件」說明需求，工程用 Case_ID 串起資料、API、附件、audit_logs 與 Dashboard。先定主軸，後面才不會各模組各說各話。

目的 2

把判斷前移

先在 Intake 判斷是否與合約、專案、付款、預算有關，避免所有資料都被塞成同一種表單，也避免非正式專案被誤建 Project_ID。

目的 3

定義交易邊界

合約、付款、核銷、發票不是單純畫面欄位，而是不同 Service 與資料表的寫入交易。流程圖要讓後端知道哪一步要開 transaction、哪一步只做查詢與提示。

業務流程圖

實線是主要作業鏈，虛線是條件關聯或資料來源。重點是「發票不直接掛合約」，而是由 Contract → Payment → Expense → Invoice 形成核銷追溯鏈。

決策分流矩陣

Intake 的本質是分流器。助理畫圖是為了把「什麼情況要建什麼 ID」先講清楚，讓 UI、API、DB、測試可以共用同一套判斷。

判斷問題 是 否 工程輸出
是否與合約相關？ 建立或關聯 Contract_ID，必要時建立 Contract_Relation。 Contract_ID 可空，但 Case_ID 必填。 contract_service.resolve_contract_scope()
是否符合正式專案？ 建立 Project_ID，記錄公司級 / 處級 / 部級、跨公司、主管關注。 維持非正式專案，不建立 Project_ID。 project_policy.should_create_project()
是否產生付款或預算需求？ 建立 Payment_ID，展開期數，觸發 Budget_Check。 僅保留案件、合約或專案說明，暫不建立付款。 payment_service.create_schedule_with_budget_check()
是否需要核銷與發票？ 建立 Expense_ID 與 Invoice_ID，必要時建立 Invoice_Allocation。 僅列入上簽規劃與 Dashboard 追蹤。 expense_service.claim_and_invoice()
是否來自 Excel / PDF / AI？ 寫入 source_references，AI 建議需人工確認。 記錄系統建立人與時間。 source_service.attach_evidence()

開發切分

依照流程圖，第一版不要先追求大而全，而是先把 Case_ID 主軸、Intake 分流、Payment / Budget / Expense 交易與 audit_logs 打通。

1
建立 FastAPI 骨架與 /health 設定 app/main.py、config、router、OpenAPI；DB 未設定時回傳可讀錯誤。
2
建立 Case / Intake API POST /api/signing-cases 回傳 Case_ID、建議建立的資料節點與下一步 action。
3
建立 Contract / Project / Payment Service 用單一 Orchestrator 包裝交易，讓關聯資料與 audit_logs 一起成功或一起 rollback。
4
接上 Dashboard 與下鑽查詢 每個摘要卡都能下鑽到條件清單，再進案件履歷與來源追溯。
5
補匯入、回匯、AI 建議暫存 Excel / PDF / AI 都先進暫存與來源表，人工確認後才更新正式資料。
不可省略

工程驗收條件

  • 四角色入口仍要存在。
  • 所有新增、修改、作廢、確認與回匯都寫入 audit_logs。
  • Dashboard 統計需符合：全部 = 未啟動 + 進行中 + 逾期 + 完成。
  • AI 建議與正式金額必須分離。
資料主線

最小可落地資料鏈

Case_ID → Contract_ID 或 Project_ID → Payment_ID → Budget_Check → Expense_ID → Invoice_ID → Invoice_Allocation → audit_logs。第一版只要這條鏈穩，後續匯入、搜尋、報表快照與 AI 建議都能接上。
