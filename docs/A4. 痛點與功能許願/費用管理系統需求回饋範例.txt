# 費用管理系統需求回饋範例

填寫人：主管 / 使用者代表  
角色：主管檢視費用、預算、簽呈、合約與付款進度  
日期：

## 1. 目前希望主管頁面怎麼呈現？

主管希望畫面左邊可以用四個大項分類，讓人一進來就知道要看哪一類資料。

四個大項如下：

1. 預算
2. 簽呈
3. 合約
4. 費用付款

每個大項點進去後，可以看到下面的細項資料，不要只是一張大表，否則不夠直覺。

---

## 2. 預算頁面希望看到什麼？

預算希望先分成兩類：

### 預算內

指去年已經申請並核定的預算。

希望可以看到：

- 預算代號
- 預算名稱
- 預算年度
- 原核定金額
- 已使用金額
- 剩餘金額
- 對應的簽呈
- 對應的合約
- 對應的付款紀錄
- 目前狀態：正常 / 已終止 / 已用罄 / 待確認

### 預算外

指臨時發生的專案或非年度預算內項目。

希望可以看到：

- 專案名稱
- 申請原因
- 預估金額
- 實際金額
- 對應簽呈
- 對應合約
- 對應付款
- 是否已補簽或補核准

---

## 3. 如果預算被終止，費用要怎麼處理？

希望系統不要直接刪除預算，而是保留紀錄，並標示為「已終止」。

AI 建議可以分成幾種情況處理：

1. 已付款的費用  
   保留付款紀錄，標示為已發生費用，不能直接刪除。

2. 已簽約但尚未付款  
   系統提醒需要確認合約是否終止、展延或改由其他預算支付。

3. 已簽呈但未簽約  
   系統標示為待確認，提醒承辦確認是否取消或改案處理。

4. 尚未發生費用  
   剩餘預算可以標示為凍結、收回或轉入其他預算，但需要留下處理原因。

希望系統可以要求承辦填寫終止原因，並保留操作紀錄，方便日後查詢。

---

## 4. 點進一個流程案件時，希望看到什麼？

例如點進「防火牆採購」這個案件，希望畫面可以一次看到完整關聯資料。

### 案件基本資料

- 案件名稱：防火牆採購
- 負責承辦
- 所屬部門
- 預算年度
- 案件狀態
- 目前流程進度

### 預算資訊

- 去年申請的預算代號
- 預算名稱
- 預算內 / 預算外
- 核定金額
- 已使用金額
- 剩餘金額
- 預算是否終止

### 簽呈資訊

承辦需要輸入簽呈號碼，並上傳 PDF。

希望可以看到：

- 簽呈號碼
- 簽呈日期
- 簽呈主旨
- 簽呈狀態
- PDF 附件
- 上傳人與上傳時間

### 合約資訊

合約也希望用相同方式管理。

希望可以看到：

- 合約號碼
- 廠商名稱
- 合約期間
- 合約金額
- 合約狀態
- PDF 附件
- 是否對應原簽呈

### 費用付款資訊

費用付款希望可以依付款週期分類。

付款週期包含：

- 每月
- 每季
- 每年
- 不定期

希望可以看到：

- 應付款日期
- 實際付款日期
- 付款金額
- 付款狀態
- 對應月份 / 季度 / 年度
- 是否已超過預算
- 是否需要主管確認

---

## 5. 目前畫面不夠直覺的地方

主管覺得目前畫面比較像資料表，還不夠直覺。

希望改善方向：

1. 左側先用「預算 / 簽呈 / 合約 / 費用付款」四大分類。
2. 點進案件後，用一個流程畫面串起來。
3. 不要讓使用者自己找關聯資料，系統要把預算、簽呈、合約、付款自動串在同一頁。
4. 每個區塊都要能看到狀態，例如正常、待補件、已終止、待付款、已付款。
5. PDF 附件要可以直接點開，不要只顯示檔名。
6. 金額異常或預算終止時，要有明顯提醒。

---

## 6. 希望系統達成的效果

主管希望未來看一個案件時，不需要分別去問預算、簽呈、合約和付款資料在哪裡。

只要點進案件，例如「防火牆採購」，就可以看到：

- 這筆費用是預算內還是預算外
- 去年申請的預算代號是什麼
- 簽呈號碼與 PDF
- 合約號碼與 PDF
- 費用是月付、季付、年付或不定期
- 目前已經付了多少
- 還剩多少預算
- 如果預算終止，後續費用怎麼處理

整體來說，希望主管頁面可以從「看資料」變成「看關聯、看狀態、看風險」。
